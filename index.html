About

A backend engineer who wants to understand how things work under the hood

I started programming in 2007 and have worked professionally since 2014. My first job was at a university, where I built its internal software: an anti-plagiarism system in PHP and Java, a document registry and a task tracker. I also wrote desktop applications in Delphi, including FASM Editor.

From 2016 to 2018 I worked on Java and Kotlin backends: a plugin-based REST service over third-party queue systems, a RabbitMQ-driven ingestion service for company registry data, and Spring Boot microservices on AWS. Since 2018 my work has been mainly PHP and Symfony: products in healthcare, domain registration and network monitoring, then five years on a group of high-traffic consumer products, and now a SaaS platform for online businesses.

Outside of work I learn by building small, simplified versions of the mechanisms backend systems depend on — worker pools, job queues, an event-driven cache server, an HTTP server, a database engine with a write-ahead log — and keep them as reference notes. I prefer hands-on engineering to people management.

Monolith integration tests

systeme.io · 2026

Context
A large Symfony monolith with an integration test suite that runs against real databases in Docker.
Problem
The suite was slow, and the test setup was duplicated across test cases.
Contribution
  • Found where the time went: debug mode and Xdebug in test runs, and real network calls — error reporting and internal APIs — made from inside tests.
  • Replaced those calls with test doubles, enabled OPcache for CLI runs and added parallel runs with ParaTest.
  • Added a Doctrine query counter, so tests can assert how many queries a code path makes.
  • Introduced a shared bootstrap for integration tests, split the fixtures and moved test service configuration out of the main config.
  • Gave each git checkout its own test stack, so several worktrees can run the suite at once.
